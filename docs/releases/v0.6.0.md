# ccr 0.6.0 — themes and a boxed layout

Released 2026-10-12 · [CHANGELOG](../../CHANGELOG.md#060---2026-10-12) · [compare](https://github.com/kylinfish/claude-code-resume/compare/v0.5.0...v0.6.0)

`ccr` looked like a plain 256-color terminal tool. This release gives it a
Neovim-picker look: a Tokyo Night default, four more palettes, and a stacked,
boxed layout on recent fzf.

## Highlights

- **Tokyo Night is the new default.** Every bit of color — background,
  text, borders, box labels, recency colors, the process pane's highlights,
  warnings — comes from one palette of semantic roles, so the whole picker now
  reads as one consistent theme instead of a grab-bag of ANSI codes.
- **Four more themes.** `catppuccin` (Mocha), `kanagawa` (Wave), `gruvbox`
  (Dark), and `classic` — near-identical to the pre-0.6 look, for anyone who'd
  rather keep it. Pick one with `-t`/`--theme <name>` or `CCR_THEME` (`--theme` wins when
  both are set); an unknown name warns on stderr and falls back to
  `tokyonight`.
- **Theme picker.** `ccr --themes` lists the themes next to a live preview — a
  small ccr screen drawn in the highlighted theme, on its own background.
  `Enter` saves the choice to `~/.config/ccr/theme`, which becomes the default
  (`--theme` > `CCR_THEME` > saved theme > `tokyonight`); `Ctrl-Y` only prints
  `export CCR_THEME=…`.
- **Truecolor, with a 256-color fallback.** Themes render in full 24-bit color
  when `$COLORTERM` is `truecolor` or `24bit`, and automatically fall back to
  the nearest xterm-256 color otherwise — no washed-out or wrong colors on an
  older terminal.
- **A boxed layout on fzf ≥ 0.58.** Processes, search, sessions, and preview
  each sit in their own titled, rounded-border box, all themed from the same
  palette. The key-hint line needs fzf ≥ 0.63 (older fzf shows the hints as the
  last line of the Processes box instead), and the single-row pointer gutter
  needs ≥ 0.66. Older fzf keeps the familiar single-border layout — now
  themed too. Force either one with `CCR_LAYOUT=boxed` / `CCR_LAYOUT=classic`;
  an unsupported combination warns and falls back automatically, and a version
  of `fzf --version` that can't be parsed falls back to `classic` silently.

- **Colour blocks.** Section titles are filled pill badges (the section colour
  behind bold text in the theme's background colour), and each preview block
  carries a faint tint of its own colour. `classic` stays plain.
- **Blocks inside the preview.** The Preview pane is split into titled blocks
  of its own (in both layouts — ccr draws them, so any fzf version works) — 📌 Session, 🎨 Artifacts, 📄 Files and
  💬 Last prompt — drawn inside it. When the pane is at least 100 columns wide
  they sit in two columns (session and prompt left, artifacts and files right);
  narrower panes stack them. Widths count CJK and emoji as two columns, so the
  borders line up in Chinese too.

## Notes

- If `fzf --version` reports below 0.58, upgrade with `brew upgrade fzf` to get
  the boxed layout; everything still works on the older layout in the meantime.
- `classic` (the theme): the 0.5.0 palette, near-identical. A few preview and
  process-pane tints — plus chrome text (key hints, the process-pane title,
  warnings) — now share one role each, so e.g. the hints are grey instead of
  ANSI-dim and the process-pane title is no longer bold.
- Theme and layout are independent settings — any theme works with either
  layout.

# ccr 0.6.0：主題與分框版面

發布日期 2026-10-12

`ccr` 原本只是個樸素的 256 色終端機工具。這一版讓它看起來更像 Neovim 的選單：
預設改用 Tokyo Night，另外提供四種配色，並在較新版的 fzf 上換成分框版面。

```
╭ ⚙ 背景 process · 2 ───────────────────────────────────────────────────────────────────────────╮
│  -       PID 4242   59.1% CPU   45 MB  webpack --watch    ~/payments                          │
│  :5173   PID 6060    0.0% CPU   38 MB  vite --port 5173  ~/acme-api  → http://localhost:5173  │
╰───────────────────────────────────────────────────────────────────────────────────────────────╯
╭ 🔍 搜尋 · time ───────────────────────────────────────────────────────────────────────────────╮
│ ❯ jwt                                                                                    3/14 │
╰───────────────────────────────────────────────────────────────────────────────────────────────╯
╭ Session 列表 ─────────────────────────────────────────────────────────────────────────────────╮
│▌   剛剛 │ ⚙✦ Add JWT auth to the API gateway         │ ~/code/acme-api                        │
│  2 分鐘前 │    修 checkout 不穩定的整合測試             │ ~/code/storefront                   │
╰───────────────────────────────────────────────────────────────────────────────────────────────╯
 Enter 開啟 ^R 遠端 ^F 分支 ^Y 只印 ^L 產出 ^X 已清理 ^T/^O/^G 排序
╭ 預覽 ─────────────────────────────────────────────────────────────────────────────────────────╮
│ 📌 Add JWT auth to the API gateway                                                            │
╰───────────────────────────────────────────────────────────────────────────────────────────────╯
```

## 重點

- **預設改用 Tokyo Night**：背景、文字、邊框、區塊標籤、時間新舊顏色、process
  區的高亮、警告訊息——所有顏色都來自同一套語意化的配色表，整個選單現在是
  一致的主題，不再是各自為政的 ANSI 色碼。
- **再加四種主題**：`catppuccin`（Mocha）、`kanagawa`（Wave）、`gruvbox`
  （Dark），以及 `classic`——幾乎就是 0.6 之前的配色，給想維持原樣的人。
  用 `-t`／`--theme <name>` 或 `CCR_THEME` 切換（兩者都設定時 `--theme` 優先）；
  未知的主題名稱會在 stderr 印出警告並改用 `tokyonight`。
- **主題選擇器**：`ccr --themes` 列出所有主題並即時預覽——用選到的主題（含背景色）
  畫出縮小版的 ccr 畫面。`Enter` 存到 `~/.config/ccr/theme` 並成為預設
  （`--theme` > `CCR_THEME` > 存下的主題 > `tokyonight`）；`Ctrl-Y` 只印出
  `export CCR_THEME=…`。
- **Truecolor，可退回 256 色**：`$COLORTERM` 是 `truecolor` 或 `24bit` 時以
  24-bit 全彩顯示，否則自動換成最接近的 xterm-256 色，避免舊終端機顏色跑掉。
- **fzf ≥ 0.58 的分框版面**：process、搜尋、session 列表、預覽各自獨立成一個
  圓角邊框的區塊，全部套用同一套配色。按鍵提示那一行需要 fzf ≥ 0.63（版本較舊
  時提示會變成 Processes 框的最後一行），單列指標的 gutter 需要 ≥ 0.66。版本更舊
  的 fzf 維持原本的單一邊框版面——現在也套用主題色。可用 `CCR_LAYOUT=boxed`／
  `CCR_LAYOUT=classic` 強制指定；不支援的組合會印出警告並自動退回，無法解析的
  `fzf --version` 則靜默退回 classic 版面。

- **色塊**：各區塊的標題改成實心的色塊標籤（區塊色當底、主題背景色的粗體字），
  預覽裡每個小框也有淡淡的同色底；`classic` 維持原樣。
- **預覽區內再分區塊**：預覽區裡再依內容畫出各自帶標題的區塊（兩種版面都有，由 ccr 自己畫，任何 fzf 版本都適用）——
  📌 對話、🎨 Artifacts、📄 產生的檔案、💬 最後的 prompt。預覽區寬度 ≥ 100 欄時
  分成左右兩欄（左：對話與 prompt；右：Artifacts 與檔案），較窄時由上而下排列。
  寬度計算把中文與 emoji 當兩欄，中文標題的框線也能對齊。

## 注意

- 如果 `fzf --version` 顯示低於 0.58，執行 `brew upgrade fzf` 就能用上分框版面；
  在那之前所有功能在舊版面上一樣正常運作。
- `classic` 主題：幾乎就是 0.5.0 的配色。部分 session 列、process 區與預覽的
  色調，連同標頭文字（按鍵提示、process 區標題、警告訊息）現在共用同一個配色
  角色，所以提示變成灰色而不是 ANSI 的 dim 樣式，process 區標題也不再是粗體。
- 主題與版面是互相獨立的設定，任何主題都能搭配任一種版面。
