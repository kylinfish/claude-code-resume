# ccr 0.4.0 — `ccc`: Claude Code + Codex

Released 2026-10-01 · [CHANGELOG](../../CHANGELOG.md#040---2026-10-01) · [compare](https://github.com/kylinfish/claude-code-resume/compare/v0.3.0...v0.4.0)

`ccr` stays Claude Code only. The new **`ccc`** command is the same script under
another name, with your [OpenAI Codex](https://github.com/openai/codex) sessions
in the same list.

```
codex  │   9m ago │   Fix the rate limiter                     │ ~/code/acme-api
claude │ just now │ ⚙ Add JWT auth to the API gateway          │ ~/code/acme-api
claude │   1d ago │   Teach the team Claude Desktop features   │ Desktop · ~/code/handbook
```

## Highlights

- **One picker for both tools.** Codex threads sit next to Claude Code, Desktop and
  expired sessions, sorted together.
- **Tool column.** Each row starts with `claude` or `codex`, so typing `^codex` or
  `^claude` in the search filters by tool. `Ctrl-A` cycles all → Claude → Codex.
- **Native actions.** `Enter` runs `codex resume <id>`, `Ctrl-F` runs `codex fork <id>`,
  `Ctrl-Y` prints the command. Codex has no Remote Control, so `Ctrl-R` says so and
  stops. `ccc --last` resumes the most recent session of either tool.
- **Codex preview** shows the git branch, model and tokens used.
- **Robust reading.** Threads come from `~/.codex/state_*.sqlite`, opened read-only
  with columns looked up by name. If that index is missing or unreadable, `ccc` falls
  back to the `~/.codex/sessions/**/rollout-*.jsonl` files and `session_index.jsonl`.
  Only interactive, unarchived threads (`cli` / `vscode`) are listed; subagent,
  review and MCP threads are skipped. `CODEX_HOME` is honoured.
- **Process pane** now also covers Codex projects, and never lists `codex` itself
  (including `node …/codex` shims) or the MCP servers it starts.

## Install / upgrade

`./install.sh` now links both `ccr` and `ccc` into `~/.local/bin`. Messages name the
command you ran (`ccr:` or `ccc:`). Set `CCR_CODEX=1` to get Codex sessions while
running as `ccr`.

# ccr 0.4.0：`ccc`，Claude Code + Codex

發布日期 2026-10-01

`ccr` 維持只看 Claude Code。新的 **`ccc`** 是同一支腳本換個名字執行，把
[OpenAI Codex](https://github.com/openai/codex) 的 session 一起放進同一個列表。

## 重點

- **一個選單看兩種工具**：Codex thread 與 Claude Code、Desktop、已清理的 session 一起排序。
- **工具欄**：每一列開頭是 `claude` 或 `codex`，搜尋時輸入 `^codex` 或 `^claude` 就能依工具篩選；
  `Ctrl-A` 切換：全部 → Claude → Codex。
- **原生動作**：`Enter` 執行 `codex resume <id>`，`Ctrl-F` 執行 `codex fork <id>`，`Ctrl-Y` 印出指令。
  Codex 沒有 Remote Control，`Ctrl-R` 會提示並取消。`ccc --last` 會續兩邊之中最近的一個 session。
- **Codex 預覽**：顯示 git branch、model 與 token 用量。
- **穩定讀取**：以唯讀方式開 `~/.codex/state_*.sqlite`，並依欄位名稱讀取；索引不存在或讀不到時，
  改讀 `~/.codex/sessions/**/rollout-*.jsonl` 與 `session_index.jsonl`。只列互動式、未封存的 thread
  （`cli`／`vscode`），不列 subagent、review、MCP thread。支援 `CODEX_HOME`。
- **Process 區**也涵蓋 Codex 專案，且不會列出 `codex` 本身（含 `node …/codex` 包裝）與它啟動的 MCP server。

## 安裝／升級

`./install.sh` 會同時把 `ccr` 與 `ccc` 連結到 `~/.local/bin`。錯誤訊息會用你執行的指令名稱
（`ccr：` 或 `ccc：`）。想在 `ccr` 也看到 Codex session，可設定 `CCR_CODEX=1`。
