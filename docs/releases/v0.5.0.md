# ccr 0.5.0 — what each session produced

Released 2026-10-12 · [CHANGELOG](../../CHANGELOG.md#050---2026-10-12) · [compare](https://github.com/kylinfish/claude-code-resume/compare/v0.4.0...v0.5.0)

Sessions leave things behind: claude.ai artifacts, reports, scripts, edited
code. This release shows them next to the session and opens them in one key.

```
🎨 Artifacts (1)
  API 認證流程圖  3 versions · 2026-10-12
    https://claude.ai/code/artifact/…
    ./docs/auth-flow.html ✓
📄 files written (3)
  + ./tests/auth.test.ts ✓
  ~ ./src/routes/gateway.ts ✓
  + ./src/middleware/auth.ts ✓
```

## Highlights

- **Artifacts in the preview.** Claude Code sessions that published claude.ai
  artifacts list each one with its title, number of versions, last update, link,
  and the local source file (`✓` if it still exists, `✗` if not).
- **Files written.** Files a session created (`+`) or changed (`~`), newest first,
  with `✓` / `✗`. Claude Code's come from its `Write` / `Edit` calls; Codex's from
  the `FileChange` records in each thread's rollout. Files in temp and scratchpad
  dirs are skipped, since they are usually gone by the time you look.
- **`✦` mark** on every session that has artifacts or files written, next to the
  `⚙` for running processes.
- **`Ctrl-L` opens one** — an artifact in the browser, a file in its default app.
  With several, a small picker comes up first; files that no longer exist aren't
  offered.
- **Process pane** shows `node ./node_modules/.bin/vite --port 5173` as
  `vite --port 5173`, so the tool and its flags fit.

## Also in this release

- `README.md` (English) and `README.zh-TW.md` (繁體中文) are separate files with a
  language switch; features are grouped into sections.
- The banner shows `ccr / ccc` and the current UI.
- `demo/setup.sh` / `demo/teardown.sh` build a fake, self-contained set of
  sessions, artifacts and dev servers for recording demos.
- `tests/run.sh`: an integration test suite (57 checks) that runs `ccr` / `ccc`
  against a throwaway fixture with stub `claude`, `codex`, `fzf`, `ps` and `lsof`.

## Notes

- Artifacts and files are read during the scan and cached with the index; the
  first run after upgrading re-reads each transcript once.
- The records come from Claude Code's and Codex's internal formats. If they change,
  the sections simply stay empty; nothing else is affected.

# ccr 0.5.0：每個 session 產生了什麼

發布日期 2026-10-12

session 會留下東西：claude.ai artifact、報告、腳本、改過的程式碼。這一版把它們列在 session 旁邊，
按一個鍵就能開啟。

## 重點

- **預覽列出 Artifacts**：發布過 claude.ai artifact 的 Claude Code session，會列出每個 artifact 的標題、
  版本數、最後更新時間、連結，以及本機原始檔（還在顯示 `✓`，不在了顯示 `✗`）。
- **產生的檔案**：session 新增（`+`）或修改（`~`）的檔案，最新的在上，並標示 `✓`／`✗`。
  Claude Code 取自 `Write`／`Edit` 呼叫，Codex 取自每個 thread rollout 裡的 `FileChange` 紀錄。
  暫存目錄與 scratchpad 的檔案不列，因為通常一下就被清掉了。
- **`✦` 標記**：有 artifact 或產生檔案的 session，會在 `⚙` 旁標 `✦`。
- **`Ctrl-L` 開啟**：artifact 用瀏覽器開，檔案用預設 App 開；有多個時先跳出小選單，已不存在的檔案不會列入。
- **Process 區**把 `node ./node_modules/.bin/vite --port 5173` 顯示為 `vite --port 5173`，工具名稱與參數都看得到。

## 這一版也包含

- `README.md`（英文）與 `README.zh-TW.md`（繁體中文）拆成兩個檔案並可切換，功能介紹分成小節。
- banner 改成同時呈現 `ccr / ccc` 與目前的介面。
- `demo/setup.sh`／`demo/teardown.sh`：建立一組假的、獨立的 session、artifact 與 dev server，方便錄 demo。
- `tests/run.sh`：整合測試（57 項），以假的 `claude`、`codex`、`fzf`、`ps`、`lsof` 在暫時的 fixture 上執行 `ccr`／`ccc`。

## 注意

- Artifact 與檔案在掃描時讀取並跟索引一起快取；升級後第一次執行會把每個對話紀錄重新讀一次。
- 這些紀錄來自 Claude Code 與 Codex 的內部格式，若格式改變，這兩個區塊只會變成空的，不影響其他功能。
